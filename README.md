# X5 Loyalty System

Мобильное веб-демо игровой программы лояльности для «Пятёрочки».

Проект превращает обычную покупку в один понятный следующий ход. После валидного чека AI-policy **QuestRank** выбирает не приз, а сам поведенческий рычаг: завершить личный прогресс, внести вклад в цель своей точки или передать заработанное близкому — либо не вмешиваться вовсе. Материальная награда используется только там, где она нужна для входа или milestone, и дальше её стоимость снижается.

## Основная идея

- единая короткая оболочка «Чекпоинт»: чек → один маршрут → один следующий ход → постоянный результат;
- три механики каталога: личный финиш, «Своя Пятёрочка» и семейная эстафета;
- QuestRank выбирает механику, окно, подкрепление и стоимость — либо `no_action`;
- подкрепление отдельно от механики: supplier-funded trial, баллы, цифровой unlock, привилегия или только прогресс;
- reward fading: стоимость награды снижается, чтобы отделить интерес от скидки;
- сумма чека не покупает статус и влияние;
- LLM только объясняет уже выбранное действие и не меняет его условия.

Подробности — в [описании проекта](docs/project/project-description.md) и [продуктовых материалах](docs/project/product-materials.md).

## Что реализовано

- адаптивная копия главного экрана приложения «Пятёрочки»;
- интерфейс для мобильной ширины 360–430 px;
- основной дизайн рассчитан на экран 390×844 px;
- нижняя навигация;
- переход между главной страницей и интерактивным игровым профилем со сбросом прокрутки;
- безлимитный демо-режим наградной коробки: ручная тряска, анимация открытия и возможность сразу открыть следующую коробку;
- случайное выпадение одного из 24 тематических предметов с тремя уровнями редкости;
- автоматическое добавление предмета в инвентарь; повторный предмет увеличивает его количество в одной ячейке;
- четыре ячейки скидок с переносом мышью/пальцем и запасным управлением через последовательные нажатия;
- создание скидки из четырёх предметов: предметы расходуются, а тематические сочетания дают бонус к силе скидки;
- семь рецептов-подсказок, итоговая скидка от 5% до 18% и редкость результата, рассчитанная из редкости вложенных предметов;
- полноэкранная карточка результата, активная скидка рядом с персонажем и открываемый EAN‑13 штрихкод;
- расширяемый инвентарь с восемью стартовыми ячейками и демонстрационные задания недели;
- сохранение инвентаря и одной активной скидки в `localStorage`; ранее сохранённый таймер коробки игнорируется, пока включён безлимитный демо-режим;
- демонстрационные данные без подключения backend.

Коробка, инвентарь, создание скидки и переходы «Главная»/«Профиль» интерактивны. Каталог, «Апельсин» и выполнение заданий пока выполняют только демонстрационную функцию. Штрихкод имеет корректную структуру EAN‑13, но не зарегистрирован в кассовой системе и не даёт реальную скидку.

## Шансы выпадения предметов

При каждом открытии сначала определяется редкость, затем случайно выбирается один из восьми предметов этой редкости:

| Редкость | Шанс из одной коробки | Шанс конкретного предмета |
| --- | ---: | ---: |
| Обычный | 70% | 8,75% |
| Эпический | 25% | 3,125% |
| Легендарный | 5% | 0,625% |

В демоверсии нет дневного лимита или паузы между открытиями. Выбор выполняется локально в браузере. В production выпадение и ограничение частоты должны рассчитываться на сервере, чтобы пользователь не мог изменить результат через клиентский код.

## Создание скидки

Пользователь переносит предметы из инвентаря в четыре ячейки. На мобильном устройстве можно также нажать на предмет, а затем на нужную ячейку. Интерфейс показывает ближайший тематический рецепт и предметы, которых не хватает. После заполнения всех ячеек кнопка создания становится активной; по одной копии каждого выбранного предмета списывается из инвентаря.

Сила предмета определяется редкостью: обычный — 1, эпический — 2, легендарный — 3. Сумма четырёх предметов даёт базовую скидку 5%, 7%, 10%, 13% или 15%. Три разных совпадения с одним рецептом добавляют 2%, четыре — 3%; итог ограничен 18%. Результат получает обычную редкость при силе до 6, эпическую при силе 7–9 и легендарную при силе 10–12.

Доступны семь тематических направлений: «Доброе утро», «Свежий выбор», «Вечер без готовки», «Азиатский ужин», «Ужин шефа», «Сладкая пауза» и «Домашний запас». Любое сочетание остаётся допустимым: если рецепт не собран, скидка применяется к категории самого редкого выбранного предмета без тематического бонуса.

В демоверсии одновременно хранится одна активная скидка: новая заменяет предыдущую. Её значок появляется рядом с персонажем и открывает штрихкод. Выдача, срок действия, одноразовое погашение и проверка скидки кассой потребуют серверной реализации.

## Следующие этапы

Порядок задан планом работ в [описании проекта](docs/project/project-description.md).

1. Собрать три пользовательских экрана трёх маршрутов и консоль продакта.
2. Показать три синтетических профиля, для которых policy принимает разные решения, включая `no_action`.
3. Сгенерировать синтетические истории чеков и поведенческие признаки.
4. Реализовать кандидатов, фильтры, score и exploration в QuestRank.
5. Добавить смену фазы reward fading и состояние трёх механик.
6. Добавить grounded LLM-объяснение с валидатором и fraud/delayed-кейс.
7. Добавить управляемый сброс демо и синхронизацию игрового прогресса с тестовыми профилями.

## Локальный запуск

Требуется Bun 1.3.14.

```bash
bun install
bun run dev:webapp
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:5173
```

## Проверка проекта

```bash
bun run typecheck:webapp
bun run lint
bun run test:webapp
bun run build:webapp
```
