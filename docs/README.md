# Документация

Здесь лежат два набора документов, и путать их не нужно.

- **[`project/`](project/)** — материалы проекта «X5 Чекпоинт»: кейс, продуктовые решения, презентация.
  На русском, это содержательная часть работы.
- **Файлы в этой папке** — инженерные документы шаблона, на котором собран репозиторий. На английском,
  описывают устройство кода и инфраструктуры. Какие из описанных возможностей реально включены в
  проекте, фиксирует [`CHECKLIST.md`](../CHECKLIST.md), а не эти документы.

## Проектные материалы

| Документ | Что внутри |
| --- | --- |
| [Описание кейса](project/case-brief.md) | Исходная постановка от кейсодателя и Q&A: скоуп, критерии успеха, данные по сегментам. Первоисточник для всего остального. |
| [Context pack](project/context-pack.md) | Рабочий контекст команды: решение, развилки, требования кейса против наших ответов, desk research, гипотезы, открытые вопросы кейсодателю. Точка входа для нового участника или агента. |
| [Описание проекта](project/project-description.md) | Основной сдаточный документ: QuestRank и каталог механик, продуктовое и техническое решение, экономика подкрепления, дизайн проверки, ограничения, план работ. Раздел 2 фиксирует, что изменилось относительно v4. |
| [Продуктовые материалы](project/product-materials.md) | Decision log v4 → v5, product brief, каталог механик, карта доказательств, границы MVP, traceability продукт → техника, критерии успеха и эксперимент, риски. |
| [Презентация](project/deck.pptx) | Слайды защиты: 15 слайдов вокруг выбора механики, reward fading и трёх решений policy. |

Версия и дата актуальности стоят в шапке каждого документа, поэтому в именах файлов их нет:
новая версия перезаписывает тот же файл, а история остаётся в git. Текущая — **v5 от 04.09.2026**;
диффы к предыдущим версиям смотрите через `git log -- docs/project`.

Нумерация гипотез H1–H7 общая у context pack и продуктовых материалов; при правке одного документа
проверяйте второй. Описание кейса версий не имеет — это исходник кейсодателя.

## Инженерная документация

Начинать стоит с архитектуры — она задаёт границы, на которые ссылаются остальные документы.

| Документ | О чём |
| --- | --- |
| [ARCHITECTURE.md](ARCHITECTURE.md) | Границы модулей и направление зависимостей, контракты в `packages/contracts`, прогрессивный DDD-lite, три механизма работы вне запроса, условия для realtime-инфраструктуры. |
| [WEB_SURFACES.md](WEB_SURFACES.md) | Кто чем владеет между `website`, `webapp`, `mobile` и `backend`: публичные данные, корзина, один браузерный чекаут, платежи. Читается до любой работы с продуктовыми данными. |
| [BACKGROUND_JOBS.md](BACKGROUND_JOBS.md) | Выбор между `background-tasks.ts`, outbox и `jobs.ts`, один реестр задач и три процесса-раннера, расписания. |
| [TESTING.md](TESTING.md) | Пирамида проверок и правило выбора самой узкой устойчивой границы; когда оправдан браузерный E2E. |
| [LOCAL_DATABASE.md](LOCAL_DATABASE.md) | Локальный PostgreSQL 18 через Docker Compose, требования Prisma, что делать без Docker. |
| [STORAGE.md](STORAGE.md) | Приватные файлы и медиа: драйверы `filesystem` и `s3` за одним портом, контракт загрузки. |
| [EMAIL.md](EMAIL.md) | Транзакционная почта: четыре драйвера за одним портом, сброс пароля как эталонный сценарий. |
