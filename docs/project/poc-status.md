# Локальный PoC: проверки и незакрытые задачи

Срез после интеграции исправлений от **06.09.2026**, включая текущие локальные изменения. Команды выполняются из корня репозитория. Этот документ фиксирует техническую приёмку; описание продукта и запуск находятся в [README](../../README.md).

## Подтверждённые проверки

Итоговая приёмка: **56 тестов Python-движка**, **27 тестов оценки**, **24 теста общих контрактов**, **120 web-тестов** и **13 браузерных сценариев** прошли. Также проходят TypeScript, ESLint, архитектурная проверка, полная сборка и три прежних валидатора RecSys. Браузерный пакет включает персональный путь, обмен с reload/принятием/отклонением/крафтом, экран «Для X5» и исходную игровую песочницу.

Повторить основные проверки:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s recsys/engine/tests -t .
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s recsys/eval -p 'test_*.py' -v
bun run test:contracts
bun run test:webapp
bun --bun run --cwd webapp e2e:demo
bun run typecheck && bun run lint && bun run architecture:check && bun run build
PYTHONDONTWRITEBYTECODE=1 python3 recsys/validate.py
PYTHONDONTWRITEBYTECODE=1 python3 recsys/validate_explanation.py
PYTHONDONTWRITEBYTECODE=1 python3 recsys/eval_creatives.py
```

Для браузерных тестов нужен установленный Chromium Playwright. При его отсутствии: `bun --bun run --cwd webapp e2e:install`. Остальные проверки описаны в [руководстве по тестированию](../TESTING.md) и [RecSys README](../../recsys/README.md).

## Что работает после интеграции

- **Персональный путь:** синтетические покупки и инвентарь → вычисленное задание → проверенная карточка → тестовый чек → обещанный цифровой предмет и демонстрационное право на SKU. Пустой и явно подготовленный профили показывают разные стадии коллекции. Четыре предмета создают скидку по существующей игровой формуле.
- **Чеки и сохранения:** покупка до публикации, будущий чек, бесплатная строка и строка с нулевой оплатой не закрывают задание. Кнопка повтора отправляет тот же чек и ключ идемпотентности. Повторное начисление исключено в локальном состоянии. Переключение профилей и перезагрузка сохраняют их отдельные обещания и инвентари; можно выбирать и снимать несколько копий одного предмета.
- **Резервы:** подготовленные предметы обеспечены по 2,50 ₽ за копию; новое обещание резервирует ещё одну копию и отдельно весь физический товар. Выдача предмета сохраняет купонный резерв, четыре копии переводятся в один купон максимумом 10 ₽. При погашении списывается фактическая экономия, остаток освобождается. Истечение невыполненного задания освобождает его резервы, заработанные права сохраняются.
- **LLM:** локальный Qwen3 1.7B через Ollama генерирует заголовок. Категорию, количество, награду и срок система собирает из утверждённых полей; текст проверяется до показа. Живой локальный ответ принят валидатором 05.09.2026. При ошибке, таймауте или нарушении правил используется явный `fallback`; YandexGPT остаётся необязательным запасным адаптером.
- **Прогресс:** уровень аватара считает разные завершённые рецепты (0–7), рейтинг — погашенную экономию в скользящем окне 28 дней. Реферальная функция начисляет один обычный предмет сохранённому пригласившему после разрешённого квалифицирующего события, резервирует 250 копеек и защищает от повторного начисления. Этот путь проверен unit-тестами; текущие демопрофили не содержат приглашения, поэтому отдельного браузерного показа реферала пока нет.

- **Обмен:** «Аня · обмен» отдаёт лишний кувшин за сковороду «Бориса · обмен» и завершает «Доброе утро» на 8%. Оба профиля подготовлены с дубликатами и двумя покупочными днями. Создание предложения и принятие дают два согласия; резерв исключает одновременный крафт. Срок — 24 часа, лимит — три завершённых обмена за последние семь дней. Миграция хранилища сохраняет старые профили; передача остаётся локальной.

- **Для X5:** отдельный экран показывает выбранное задание, причины выбора, финансирование и проверенные результаты оценки. Основной итог — после обеспечения новых непогашенных обязательств; денежный итог четырёх недель и CPA без учёта обязательств вынесены в детали. Экран явно обозначает, что финансируемый вариант пока является политикой симуляции, а не runtime-фильтром карточки.

## Аналитические результаты и ограничения

Релевантность: **40/40** допустимых профилей и **8/8** ожидаемых отказов. Разметка имеет статус `agent_draft`; проверяется подходящий цифровой предмет, а выполнимость и полезность полного задания ещё требуют человека. Независимая экспертная оценка и 5–7 пользовательских прохождений не проведены.

**Основной сценарный результат после обеспечения новых обязательств:** финансируемый первый подарок (`sponsored_onboarding`) — **+1 560,40 ₽** в среднем на 1 000 пользователей, **+1 398,90…+1 805,50 ₽** на пяти seed, **5/5** положительных итогов. Охват **16,12%**, дополнительные покупочные дни **+14,8** в среднем; расходы **3 803,60 ₽**, средний пик резерва **5 669,70 ₽**. Взвешенный CPA — **25,83 ₽**, условный порог безубыточности — **12,96 ₽** при неизменных исходах и субсидиях. В основном итоге дополнительно учтено 371,50 ₽ прироста максимальных непогашенных обязательств: денежный результат 1 931,90 ₽ минус это обеспечение даёт 1 560,40 ₽. Стартовые предметы уже обеспечены до эксперимента и повторно не вычитаются. Политика работает в оценщике и ещё не включена в runtime интерфейса. Ставки и субсидии берутся из выбранных тестовых кампаний; дополнительная маржа 95 ₽ на покупочный день и операции 1,20 ₽ на предложение — допущения. Выбор сделан после синтетического исследования; непогашенные обязательства остаются обеспечены, денежный итог четырёх недель не равен будущей прибыли. [Сравнение политик и стресс-приложение](../../recsys/eval/README.md) сохраняют альтернативы и нулевой/отрицательный миры.

Антифрод проверяется на 36 calibration-кейсах и 12 отдельно описанных final-кейсах; обе разметки агентские, final не является независимой случайной выборкой. На final у решения `reject` precision **1,00**, recall **0,17**; один из разрешённых случаев — скрытое злоупотребление. Известные ошибки сохранены: законный возврат у новой семьи может вызвать удержание, а реферальное кольцо без графовых признаков пропускается. Пороги не подгоняются под final; работающий скоринг не означает доказанной защиты реальных покупателей.

**Синтетическая проверка карточки:** 15 вымышленных персон × один live-вызов Qwen; в финальном протоколе 15/15 валидных JSON и 15/15 правильно воспроизводят следующий шаг, первую награду и правило четырёх предметов. Два предыдущих неуспешных протокола сохранены. Это проверка текста малой моделью после уточнения инструкции и JSON Schema, не пользовательское исследование: реальных участников 0, ответы «попробую» не измеряют спрос. [Артефакт](../../recsys/eval/results/persona-ux.json).

## Что ещё не закрыто

- Наблюдения реальных пользователей, подтверждённая человеком оценка релевантности, экспериментальное сравнение с фиксированным заданием и одинаковой наградой без игры; текущие сравнения используют синтетический отклик. Покупки после отдельного окна стимулирования ещё не проверены; прибыльность и формирование привычки не подтверждены.
- Право на физический товар остаётся записью в браузере. Реальная выдача и погашение на кассе, защищённый серверный реестр, сквозной глобальный бюджет и запас SKU, реальные рекламные бюджеты и покупательские данные не подключены. Локальные сохранения не защищены от ручного изменения и межвкладочных гонок.
- Персональный сценарий использует общую формулу крафта, но собственную панель выбора и окно награды. Исходная коробка с жестом встряхивания остаётся отдельной песочницей.
- Повторные товарные цели, полный Ads-аукцион и обучаемые модели остаются следующим этапом. Чувствительные категории, включая алкоголь, табак и никотин, исключены из PoC.
