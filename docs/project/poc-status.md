# Локальный PoC: проверки и незакрытые задачи

Срез после интеграции исправлений от **06.09.2026**, включая текущие локальные изменения. Команды выполняются из корня репозитория. Этот документ фиксирует техническую приёмку; описание продукта и запуск находятся в [README](../../README.md).

## Подтверждённые проверки

Итоговая приёмка: **223 автоматизированные проверки** — **70 тестов Python-движка**, **39 тестов оценки**, **8 тестов общих контрактов**, **89 web-тестов** и **17 Playwright-сценариев**. Также проходят TypeScript, ESLint, архитектурная проверка, полная сборка и три прежних валидатора RecSys. Браузерный пакет включает персональный путь, локальный Ads-аукцион с резервом, биллингом, защитой от повтора, бюджетом и частотным лимитом, обмен с reload/принятием/отклонением/крафтом, экран «Для X5» и открытие коробки с попаданием предмета в общую коллекцию.

Повторить основные проверки:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s recsys/engine/tests -t .
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s recsys/eval -p 'test_*.py' -v
bun run test:contracts
bun run test:webapp
bun --bun run --cwd webapp e2e:demo
bun run typecheck && bun run lint && bun run architecture:check && bun run build
PYTHONDONTWRITEBYTECODE=1 python3 recsys/validate.py
PYTHONDONTWRITEBYTECODE=1 python3 recsys/validate_explanation.py
PYTHONDONTWRITEBYTECODE=1 python3 recsys/eval_creatives.py
```

Для браузерных тестов нужен установленный Chromium Playwright. При его отсутствии: `bun --bun run --cwd webapp e2e:install`. Остальные проверки описаны в [руководстве по тестированию](../TESTING.md) и [RecSys README](../../recsys/README.md).

## Что работает после интеграции

- **Персональный путь:** синтетические покупки и инвентарь → вычисленное задание → проверенная карточка → тестовый чек → обещанный цифровой предмет и демонстрационное право на SKU. Первый физический подарок публикуется только при победившей рекламной кампании; следующие циклы остаются цифровыми и могут быть органическими. Пустой и явно подготовленный профили показывают разные стадии коллекции. Четыре предмета создают скидку по существующей игровой формуле.
- **Чеки и сохранения:** покупка до публикации, будущий чек, бесплатная строка и строка с нулевой оплатой не закрывают задание. Кнопка повтора отправляет тот же чек и ключ идемпотентности. Повторное начисление исключено в локальном состоянии. Переключение профилей и перезагрузка сохраняют их отдельные обещания и инвентари; можно выбирать и снимать несколько копий одного предмета.
- **Резервы:** подготовленные предметы обеспечены по 2,50 ₽ за копию; новое обещание резервирует ещё одну копию и отдельно весь физический товар. Выдача предмета сохраняет купонный резерв, четыре копии переводятся в один купон максимумом 10 ₽. При погашении списывается фактическая экономия, остаток освобождается. Истечение невыполненного задания освобождает его резервы, заработанные права сохраняются.
- **LLM:** локальный Qwen3 1.7B через Ollama генерирует заголовок. Категорию, количество, награду и срок система собирает из утверждённых полей; текст проверяется до показа. Живой локальный ответ принят валидатором 05.09.2026. При ошибке, таймауте или нарушении правил используется явный `fallback`; YandexGPT остаётся необязательным запасным адаптером.
- **Ads runtime:** контракт v2 передаёт глобальное состояние кампаний между webapp и Python. Локальный закрытый quality-adjusted first-price CPA-аукцион сравнивает минимум две кампании в молочной и кофейной категориях, до ранжирования проверяет категорию, период, доступный бюджет, частотный лимит, качество и минимальный ожидаемый прирост. Pacing меняет только порядок показа. При публикации резервируются ставка и субсидия; после свежего квалифицированного события с решением `allow` first-price CPA и субсидия списываются один раз. Повтор события не создаёт второй биллинг. Глобальный для демопрофилей ledger и его диагностика сохраняются в браузере.
- **Прогресс:** уровень аватара считает разные завершённые рецепты (0–7), рейтинг — погашенную экономию в скользящем окне 28 дней. Реферальная функция начисляет один обычный предмет сохранённому пригласившему после разрешённого квалифицирующего события, резервирует 250 копеек и защищает от повторного начисления. Этот путь проверен unit-тестами; текущие демопрофили не содержат приглашения, поэтому отдельного браузерного показа реферала пока нет.

- **Обмен:** «Аня · обмен» отдаёт лишний кувшин за сковороду «Бориса · обмен» и завершает «Доброе утро» на 8%. Оба профиля подготовлены с дубликатами и двумя покупочными днями. Создание предложения и принятие дают два согласия; резерв исключает одновременный крафт. Срок — 24 часа, лимит — три завершённых обмена за последние семь дней. Миграция хранилища сохраняет старые профили; передача остаётся локальной.

- **Для X5:** отдельный экран показывает выбранное задание, причины решения `offer`/`no_action`, победителя и компоненты Ads-ранжирования, источник финансирования, резерв, частотный лимит и состоявшийся биллинг, а рядом — результаты сравнения политик. Основной итог симуляции считается после обеспечения новых непогашенных обязательств; денежный итог четырёх недель и CPA без учёта обязательств вынесены в детали.

## Аналитические результаты и ограничения

Evaluator contract v2 для post-onboarding digital cycle: **40/40** допустимых профилей получили приемлемый предмет знакомой категории, **8/8** ожидаемых отказов вернули правильную причину. Это воспроизводимая автоматическая проверка контракта; выполнимость и полезность полного задания ещё требуют экспертной и пользовательской проверки.

**Основной сценарный результат после обеспечения новых обязательств:** финансируемый первый подарок (`sponsored_onboarding`) — **+3 845,06 ₽** в среднем на одну когорту из 1 000 синтетических пользователей за четыре недели, **+3 743,20…+4 171,80 ₽** на пяти seed, **5/5** положительных итогов. Это результат X5 по всей когорте, не выгода одному пользователю. Охват — **20,40%**, дополнительные покупочные дни — **+20,6**, расходы — **4 701,04 ₽**, средний пик резерва — **6 765,90 ₽**, фактический CPA — **26,88 ₽**, консервативный порог безубыточности — **1,22 ₽**. Денежный итог **4 301,56 ₽** минус **456,50 ₽** прироста максимальных непогашенных обязательств даёт **3 845,06 ₽**. После тех же обязательств baselines дали: broad personalized **−7 996,44 ₽**, fixed dairy **+1 024,88 ₽**, reward-only **+3 436,90 ₽**. Расчётный вклад игрового слоя относительно reward-only — **+408,16 ₽** при явно заданном синтетическом допущении об отклике; это не измеренный causal uplift. Runtime применяет ключевое продуктовое ограничение политики: первый физический SKU возможен только при рекламном финансировании. [Сравнение политик и стресс-приложение](../../recsys/eval/README.md) сохраняют одинаковые исходы и нулевой/отрицательный миры.

**Offline learned RecSys:** на 6 000 синтетических пользователей с рандомизированными treatment/control и действиями реализованы две `LogisticRegression`-модели, разница их прогнозов, `IsotonicRegression` и отдельная модель billable-события. Финальная выборка содержит **1 215** пользователей. На одинаковых held-out исходах learned profit-gated политика дала **+18 665,20 ₽**, rules-baseline — **+13 533,60 ₽**, фиксированное молочное задание — **−6 790,60 ₽**; uplift RMSE после калибровки — **0,063689**, billable AUC — **0,801916**. На пяти seed learned-политика оставалась положительной и выше rules: диапазон **+15 828,20…+19 431,60 ₽**, среднее **+17 763,76 ₽**. Это доказательство работоспособности обучаемого контура на сгенерированных данных; оно не является оценкой реального uplift X5 и модель не обслуживается runtime.

Антифрод проверяется на 36 calibration-кейсах и 12 отдельно описанных final-кейсах; обе разметки агентские, final не является независимой случайной выборкой. На final у решения `reject` precision **1,00**, recall **0,17**; один из разрешённых случаев — скрытое злоупотребление. Известные ошибки сохранены: законный возврат у новой семьи может вызвать удержание, а реферальное кольцо без графовых признаков пропускается. Пороги не подгоняются под final; работающий скоринг не означает доказанной защиты реальных покупателей.

**Синтетическая проверка карточки:** 15 вымышленных персон × один live-вызов Qwen; в финальном протоколе 15/15 валидных JSON и 15/15 правильно воспроизводят следующий шаг, первую награду и правило четырёх предметов. Два предыдущих неуспешных протокола сохранены. Это проверка текста малой моделью после уточнения инструкции и JSON Schema, не пользовательское исследование: реальных участников 0, ответы «попробую» не измеряют спрос. ## Что ещё не закрыто

- Наблюдения реальных пользователей, подтверждённая человеком оценка релевантности, экспериментальное сравнение с фиксированным заданием и одинаковой наградой без игры; текущие сравнения используют синтетический отклик. Покупки после отдельного окна стимулирования ещё не проверены; прибыльность и формирование привычки не подтверждены.
- Право на физический товар остаётся записью в браузере. Реальная выдача и погашение на кассе, защищённый серверный реестр, сквозной глобальный бюджет и запас SKU, реальные рекламные бюджеты и покупательские данные не подключены. Локальные сохранения не защищены от ручного изменения и межвкладочных гонок.
- Персональный сценарий использует общую формулу крафта, но собственную панель выбора и окно награды. Исходная коробка с жестом встряхивания остаётся отдельной песочницей.
- Повторные товарные цели, реальное обучение на экспериментальных логах и промышленная инфраструктура аукциона — аккаунты брендов, контракты, защищённый бюджетный ledger, POS-события и сверка платежей — остаются следующим этапом. Чувствительные категории, включая алкоголь, табак и никотин, исключены из PoC.
