# Независимая проверка локального PoC

Оценка держится отдельно от движка: разметка фиксируется до прогона и не подстраивается под
ответы. Все записи имеют `label_status: "agent_draft"` — статус экспертной оценки появляется
только после подтверждения человеком.

## Команды

```bash
python3 recsys/eval/build_profiles.py   # пересобирает профили и рубрику (детерминированно)
python3 recsys/eval/run_relevance.py    # релевантность: порог 28 из 40 + негативная выборка
python3 recsys/eval/simulate.py         # симуляция 1 000 пользователей, три сценария
python3 recsys/eval/fraud_eval.py       # precision / recall / ошибочные блокировки
```

Профили дополнительно проверяются общим контрактом:

```bash
bun webapp/scripts/validate-demo-payload.ts profile recsys/eval/profiles/eligible/eval-01.json
```

## Что здесь есть

| Артефакт | Что проверяет | Чего НЕ доказывает |
| --- | --- | --- |
| `profiles/eligible/` — 40 профилей | Что у каждого есть хотя бы одно приемлемое задание | Не является выборкой реальных покупателей |
| `profiles/refusal/` — 8 профилей | Что отказ наступает по правильной причине | Не покрывает все возможные отказы |
| `rubric.json` | Множество приемлемых решений на профиль | Не задаёт единственно верный ответ и не повторяет ранжирование движка |
| `run_relevance.py` | Долю попаданий и корректность отказов | Не измеряет релевантность на людях |
| `scenarios/` и `simulate.py` | Охват, расход, полный резерв и маржу в трёх мирах | Не является прогнозом эффекта X5 |
| `fraud/cases.json` и `fraud_eval.py` | Precision, recall, ошибочные блокировки, долю ручной проверки | Не переносится на реальную частоту мошенничества |
| `human-protocol.md` | Порядок коротких прохождений | Наблюдений пока нет: раздел пуст до участия людей |

## Критерий приемлемости в рубрике

Приемлемым считается задание, у которого категория есть в истории покупок профиля, а предмет
недостающий хотя бы в одном рецепте. Критерий продуктовый и допускает несколько ответов; он
намеренно не воспроизводит порядок ранжирования движка, иначе оценка была бы круговой.

Инвариант набора: у допустимого профиля обязан существовать хотя бы один приемлемый ответ.
Первая сборка набора нарушила его в двух записях — дубликаты выкупали единственный предмет
единственной знакомой категории, и приемлемых ответов не оставалось. Генератор теперь проверяет
инвариант сам и падает, если он нарушен. Разметка при этом не менялась под ответы движка.

## Текущие результаты

Прогон от 2026-09-05 на движке `poc-rules-1`:

- релевантность: 40 попаданий из 40 при пороге 28; 8 из 8 корректных отказов;
- симуляция: положительный сценарий даёт плюс, нулевой — минус, отрицательный — больший минус;
  максимальный одновременный резерв 16 802,50 ₽ при 611 показанных обещаниях;
- антифрод: precision 1.00, recall 0.80 на обеих выборках, ноль ошибочных блокировок легитимных
  семей, 33% случаев уходит на ручную проверку.

Известный пропуск: саморефералка со зрелого аккаунта с историей набирает 0.5 и получает только
`review`, а не автоматический отказ. Порог не меняется под этот случай — он объясняется
стоимостью ошибок и остаётся зафиксированным.

Все числа получены на конкретных синтетических наборах и не являются измеренным поведением
пользователей, доказанной прибыльностью или качеством антифрода в проде.
